# Original Research vs Shortcut-Audit Research

**Purpose:** a newcomer must be able to see where the original cultural-reasoning question ended, where the shortcut-audit track began, what each can and cannot claim, and what is reusable. Evidence: `docs/reconstruction/03_CHRONOLOGICAL_RESEARCH_TIMELINE.md`, `docs/reconstruction/04_EXPERIMENT_REGISTER.md` (Phase 1), and this audit's `docs/experiments/EXPERIMENT_REGISTER.md`.

---

## 1. The two questions, stated plainly

| | Original (cultural reasoning) | Shortcut-audit track |
|---|---|---|
| Question | Can LLMs understand the *culturally grounded meaning* of proverbs (vs translations/surface form)? | Can we *generate distractors* that resist shortcut solving? |
| Evidence type | Model accuracy on meaning questions; recall (FiB); explanation quality (Generation) | Blind committee agreement on options-only |
| Where it ran | Groq pilot May 2026 + Kaggle FiB/Generation pilots May 19 | OpenRouter v59–v70, June–July 2026 |
| Status | Paused after May 18 thesis invalidation + June infrastructure failures | v68 completed; v69 never run; v70 halted |
| Repository | **This one** | `saaga23/proverb_mcq` |

## 2. How the shortcut concern emerged (verified timeline)

1. **May 2026:** the original pilot measures a difficulty gap (S1 vs S2). Shortcut *mitigations* (position shuffling, contamination filter, leakage heuristic) exist from the start — shortcut *auditing* does not.
2. **May 18 (per memory export; contemporaneous docs only):** "central thesis invalidated" — the S1-vs-S2 framing proved fragile (see §3).
3. **June 4 audit (claimed):** S2's 62.5% mixes real paraphrases (claimed 24.9%, below random) with placeholder fallbacks — a *construct-validity* failure of the cultural-reasoning metric itself. **No surviving artifact computes 24.9%** — this remains a narrative claim (level 6 evidence).
4. **June 8–13:** Kaggle Groq runs collapse (2,440/2,700 API failures) + answer-key shuffle bug → the Groq path is abandoned.
5. **June 13–22:** the project reframes around a new, *verifiable* question — distractor shortcut resistance — with audit gates (HCW etc.) and the v68 production run.
6. **June 22–Jul 10:** v69 never runs (budget), v70 halts, paper-first package forms (Aug 2) around the methodology + failure taxonomy.

So the shortcut-audit track began as a **response to validity and infrastructure failures in the original track**, and then became its own research program. It did not arise from a finding about cultural understanding.

## 3. What each track's results actually license

- **Original track (May pilot):** IF the May 24 verification is accepted, models found S2 distractors significantly harder than S1 distractors (651/750 vs 369/590). This is evidence about **option difficulty**, and *tentatively* about cultural understanding — but the construct-validity dispute (unresolved) means the headline claim "models fail cultural reasoning" is **not established**. The FiB (30-item) and Generation (2,160-attempt) pilots show the formats ran; their analyses were never completed, so they support **no quantitative conclusions** today.
- **Shortcut track (v68):** distractors generated by the v68 pipeline are frequently shortcut-vulnerable (27.8% HCW). This is evidence about **the generation pipeline**, not about models' cultural competence. The v68 blind committee (56.7% accuracy options-only) is a diagnostic of distractor temptation, **not** a model-comprehension score.

## 5. Stays in the old repository

v68/v69/v70 outputs and tables, the EACL 2027 paper draft and submission package, the failure-taxonomy paper framing, `paper/**`, and all shortcut-specific hypotheses (e.g., "shortest-answer bias", "echo distractor bias"). This repository links to them for history but does not host or extend them.

## 6. What a newcomer should conclude

- The **original question is still open and unmeasured** by any surviving, undisputed experiment.
- The **shortcut-audit work is real, verified, and separate**; its methods are inputs to, not substitutes for, the cultural-reasoning study.
- The **fastest path back to the original question** is likely: resolve S2 construct validity (or replace S2), then run the FiB and Generation formats — both already piloted — with the annotation app for human validation.
